## Preserve the report
Save the original message as an .eml file with full headers. A screenshot can show what the user saw, but it does not preserve all the routing details or attachments. Record the reporting user's account, the message subject, the received time, and the incident ticket number. Keep the original message in the restricted case folder. Do not forward a suspicious attachment to coworkers as a way to ask for help.

## Review without interacting
Compare the visible sender, reply address, and return path. Read authentication results as supporting evidence rather than treating a pass as proof that the sender is safe. A compromised legitimate account can send harmful mail. Record the visible link text and the destination separately, since they can differ. Inspect URLs using approved analysis services and an isolated analysis environment. Do not enter credentials or open attachments on the user's normal workstation.

## Ask what happened
Ask whether the user only read the message, clicked a link, opened a file, or submitted information. Record the sequence and approximate times without blaming the user. A report that a password was entered requires account containment review even if the page has already disappeared. A downloaded or opened attachment also requires endpoint review. Record uncertainty explicitly when the user does not remember an action.

## Close the intake
Search for related messages using safe indicators from the case. Note which other recipients may need review, and send removal requests through the approved administrative process. Record the analyst's classification, the evidence supporting it, and any follow-up assigned to another team. Tell the reporter that the case was received and how to report additional information. Keep the full message out of public notes and training screenshots.
